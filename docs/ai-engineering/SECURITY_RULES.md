# AuraPass™ Enterprise — Security Governance & Biometric Privacy Standard

This document establishes the DevSecOps security baseline, cryptographic protocols, biometric data sovereignty rules, and credential protection procedures for AuraPass Enterprise.

---

## 1. Biometric Data Sovereignty & Legal Compliance

### 1.1 GDPR Article 9 & BIPA Mandates
Facial biometrics represent special category personal data. AuraPass enforces strict legal protections:
1. **Irreversible Feature Embeddings**:
   - The platform stores 512-dimensional floating-point embedding vectors generated by deep convolutional backbones (Facenet512, ArcFace).
   - Mathematical transformation is one-way: original face images cannot be reconstructed or reverse-engineered from embedding vectors.
2. **Zero Third-Party Cloud Transmissions**:
   - In both local air-gapped and cloud multi-tenant modes, inference executes entirely on customer-controlled server instances.
   - Raw video frames and biometric vectors are never transmitted to external AI APIs or third-party vendors.
3. **Right to Erasure (GDPR Art. 17)**:
   - When an employee is deleted, the platform automatically purges all corresponding photo files, face crops, and vector embeddings from all active model indices.
4. **Ephemeral Video Buffer**:
   - Camera video frames processed for attendance verification are processed in RAM and immediately discarded. Unsaved frames are never written to disk.

## 2. DevSecOps & OWASP ASVS Level 2 Verification

### 2.1 Authentication & Session Management
- Passwords hashed using `bcrypt` with salt rounds $\ge 12$.
- JWT access tokens signed with HMAC-SHA256 (`HS256`), expiring in 30 minutes.
- Refresh tokens rotated upon use and stored with HttpOnly, Secure, and SameSite attributes.
- Failed login attempts rate-limited via `Flask-Limiter` (maximum 10 attempts per minute per IP address).

### 2.2 Access Control & Multi-Tenant Separation
- Strict server-side authorization enforcement via `@require_auth` and `@inject_org_id` decorators.
- Every tenant query enforces `WHERE org_id = :authenticated_org_id`.
- Tenant storage directories segregated under `backend/data/orgs/<org_id>/` with no cross-directory read/write permissions.

## 4. Emergency Credential Rotation Runbook
If an active production key or database password is leaked:
1. **Invalidate Immediately**: Rotate `SECRET_KEY` and `JWT_SECRET_KEY` in production environment settings. This immediately invalidates all active sessions.
2. **Rotate Database Passwords**: Update user passwords on the PostgreSQL / SQLite server and update connection strings.
3. **Audit Access Logs**: Inspect `audit_logs` table for any unauthorized API requests during the exposure window.
4. **Log Incident**: Record event in the security incident log with remediation timeline and root-cause analysis.
